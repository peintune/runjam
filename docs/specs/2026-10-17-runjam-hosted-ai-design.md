# RunJam 内置 AI 与充值

用户要求在 RunJam 开发与 Pasteguana 相同的内置 AI 和充值。沿用已批准的共用账号/后台设计；本次实现账号 UI 和实际 Agent 调用，RunJam 其他功能继续免费。

## 用户流程

设置增加「账号与余额」：邮箱验证码登录、RunJam AI 可用余额、累计充值/消费、10 元微信充值、收支明细、刷新和退出。付款在系统浏览器打开，回到应用自动刷新并短时轮询到账。状态显示正在确认，不把打开收银台当作充值成功。余额随账号，在不同电脑登录可恢复；与 Pasteguana 钱包继续按产品分账。

商用模型页固定展示「RunJam 内置 AI」，无需用户填写模型地址或 Key。可按现有交互分配给 Claude Code/Codex/Gemini，主会话及宠物问答沿用已有模型选择。用户显式选择后才能产生付费调用，不覆盖自带模型，不改变 Agent 权限或原生配置。

## 调用与资金边界

通用 OpenAI Chat Completions 付费入口增加到现有 platform/runjam/ai/chat/completions；继续使用一套 RPC/钱包/账本/预留。兼容工具定义、assistant.tool_calls 和 tool 消息，以及流式和非流式响应。服务器固定供应商模型、Key、输出上限和单价，不信任请求中的模型或金额。真实用量校验、结算后才发送完成标志；断流/取消/不完整结果释放预留，不重复结算。

原有本地协议代理负责 Anthropic/Responses/Gemini 转换，统一在 send_chat_completions 识别内置固定端点并注入账户会话。账号会话保存在操作系统凭据库，不写 models.json、SQLite 模型表、CLI 配置或前端 localStorage；模型记录只有固定公共地址和占位符。退出后后续内置调用失败并引导登录，原有自带模型正常工作。

## UI

沿用 RunJam 现有灰白/靛蓝与深色主题，不改设置框架。账号页以余额数值为视觉重点，登录/充值为明确主操作；明细使用列表。商用模型顶端固定内置卡片，展示登录/余额状态和 Agent 分配，不显示供应商模型名、底层输入/输出价格或可编辑的假 Key。

## 验证与发布

实际 Postgres/PGlite 覆盖 RunJam 充值、跨产品隔离及扣费；模拟上游 SSE 验证工具输出、缺失用量/中断不收费、流结束顺序和请求重复。Rust 测试内置记录不可泄露账号凭据、固定端点保护和本地协议路由；Vue 测试登录/充值状态和文案。检查构建、Deno 类型、原有回归，再部署共享核心及兼容入口。生产只创建待支付收银台，不伪造到账、不消耗真实用户余额。
